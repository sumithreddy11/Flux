Flux

Flux is a secure command-line file transfer system written in Go.

It encrypts files locally using AES-256-GCM before uploading them to a server. The receiver downloads the encrypted payload, decrypts it, and verifies the resulting file using SHA-256.

Features

Secure single-file transfers

AES-256-GCM authenticated encryption

SHA-256 integrity verification

Transfer IDs

Transfer metadata

Transfer status tracking

Encrypted upload and download

CLI-based sender and receiver

Automated security tests

Running Flux

1. Start the server

From the project root:

go run ./cmd/server

The server listens on:

http://localhost:8080

2. Send a file

Open another terminal:

go run ./cmd/flux send test.txt

Flux will:

Create a transfer.

Generate an encryption key.

Calculate the original file SHA-256.

Encrypt the file using AES-256-GCM.

Upload the encrypted payload.

Store transfer metadata.

Display the transfer ID and encryption key.

Example:

========================================
          FLUX TRANSFER READY
========================================

Transfer ID(Demo Key):
b48e631013be7a30

Encryption Key(Demo key):
<secret-key>

IMPORTANT:
Keep this key safe.
Without it, the encrypted file cannot be decrypted.

Receiver command:
flux receive b48e631013be7a30 <secret-key>

3. Receive a file

go run ./cmd/flux receive <transfer-id> <encryption-key>

The receiver:

Downloads the encrypted payload.

Decrypts it using AES-256-GCM.

Calculates the SHA-256 hash of the decrypted file.

Compares it with the sender's recorded hash.

Rejects the file if integrity verification fails.

Successful verification:

Verifying SHA-256...
SHA-256 verification: PASS

========================================
        TRANSFER DECRYPTED
========================================

Download complete.

Security Model

Flux uses AES-256-GCM for authenticated encryption.

This provides:

Confidentiality

Authentication

Tamper detection

The encryption key is generated by the sender and is supplied separately to the receiver. The server receives and stores the encrypted payload, but the current protocol does not send the encryption key as part of the uploaded file payload.

SHA-256 is additionally used to verify that the decrypted file matches the expected file.

HTTP API

The current server exposes these endpoints:

Create transfer

POST /api/transfers

Creates a transfer and returns its ID and initial status.

Upload encrypted file

POST /api/transfers/{transferID}/file

Uploads the encrypted payload and records file metadata.

Relevant headers include:

X-File-Name
X-File-Size
X-File-Hash

Download encrypted file

GET /api/transfers/{transferID}/download

Returns the encrypted payload for the receiver to decrypt locally.
